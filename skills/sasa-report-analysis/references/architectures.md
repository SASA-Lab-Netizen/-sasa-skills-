# 架构选择与章节卡

## 全篇逻辑

研究对象与边界 → 为什么值得研究 → 现状/痛点 → 为什么发生 → 证据如何支持 → 可行行动与边界。

每章先写章节卡：

| 项目 | 要求 |
|---|---|
| 子问题 | 本章回答什么；为何它必须在当前位置出现 |
| 论点 | 一句可检验的判断，注明暂定/已支持 |
| 证据 | 事实、数据、案例、调查及台账编号 |
| 方法 | 选用的分析框架及其输入 |
| 图表 | 读者靠什么快速理解证据或机制 |
| 产物 | 本章结论如何成为下一章输入 |

章节顺序由依赖决定，不要求每篇都宏观→中观→微观。

## A 行业分析

摘要 → 范围与口径 → 行业规模/演进 → 价值链与竞争 → 需求/供给与核心瓶颈 → 关键机制与案例 → 情景和行动建议 → 结论、文献、附录。

不把 PEST 写成百科资料堆积；外部变化必须连接具体行业指标或竞争机制。预测明确方法、假设、区间和风险；没有可用数据不报精确市场规模。

## B 案例分析

摘要 → 问题与情境 → 案例选择依据 → 案例事实与过程 → 机制拆解 → 效果、反例与边界 → 横向比较与共性 → 行动建议 → 结论、文献、附录。

统一比较维度，例如主体、原痛点、投入、机制、成果、风险、适用条件。成功与失败对照能增强解释，但不能因为没有失败案例就编造一个。结论超出案例范围时明确其推断性质。

## C 调研报告

摘要 → 研究问题 → 调研设计 → 样本与数据质量 → 主要发现 → 分群/交叉与定性解释 → 原因与建议 → 限制 → 文献、问卷/访谈与补充数据。

必须说明对象、招募、时期、有效样本、清洗规则和量表/选项。没有回收数据时交付研究设计，不给结果。图表展示关键发现，附录保留完整工具。

## D 实证/机制研究

摘要 → 背景与文献缺口 → 理论机制与假设 → 数据/变量/识别策略 → 主要结果 → 稳健性/异质性/机制检验 → 案例或实践解释 → 政策含义、限制 → 文献、推导和补充表。

只有研究条件充分才采用。统计相关、因果识别和理论模拟分开表述；正文优先解释意义，技术推导适当移附录。负结果也是结果。

## 前后置内容

长报告可用：封面→摘要→研究思路图→目录→图表目录→正文→文献→附录。顺序可按比赛规定调整。短报告省略图表目录和独立思路页，不为凑页数重复信息。

研究思路图与正文目录共用一个章节点列表；增加章节时两者同步。箭头注明推导关系；同样的四段目录不能自动称为“研究框架创新”。
