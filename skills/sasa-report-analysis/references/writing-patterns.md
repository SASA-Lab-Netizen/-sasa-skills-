# 结论先行与层级写法

## 小节段落

`判断 → 可追溯证据 → 机制解释 → 限制/反例 → 下一步含义`

例如（纯写法示例，无真实数据）：

> 末端供应商的主要障碍可能是信用无法跨层传递。应收账款台账与访谈需要共同支持这一判断。其机制假设是核心企业信用在间接交易关系中被削弱，导致金融机构提高核验成本。但也应检查账期、抵押物与企业经营能力等替代解释。因此，下节将比较两种核验方式的成本和适用条件。

有真实结果时用明确结论；证据不足时保留“可能/待验证”，不要为了结论先行删除不确定性。

## 标题

章标题兼顾对象和判断：`3 机制分析：可信数据能否降低核验成本`。小节写具体机制：`3.1 交易可追溯性改善信息核验`。支持不足可用问题型，不把口号写成已证实结论。

默认 1/1.1/1.1.1；至少两个同级小节才有必要细分。三级以下改用段内标签/列表。序号由目录结构生成与核对，不手工随意复制。

## 摘要

问题与对象→方法和材料→最重要的 2–3 项发现→行动含义→必要限制。建议 300–500 字，比赛要求优先；不机械写“第一章…第二章…”。核心发现应与正文结论一致，不把预测或设想写成已实现成果。

## 引言、引用与结语

引言说明现实问题、已有研究/实践不足、研究问题、范围与方法。引言与摘要功能不同，避免两次重复全部结果。引用直接服务证据或定义，避免大段引文堆积。

结语逐项回答研究问题，再说明边界与未来需验证事项；不引入全新数据。小结仅在较长章节有必要时设置，产出下一章所需判断。

## 建议

把建议写成 `发现/原因→责任主体→行动→资源/前提→指标→风险与缓释`。时间、成本、收益缺依据时标为方案假设。不能所有问题都以“加强协同、完善制度”结束。

## 从报告到系列文章

先选独立命题：现状篇、机制篇、案例篇、行动篇。每篇使用同一证据台账，保留必要引用与限制；篇幅和平台适配用户请求。文章可以简化编号，但不能丢失结论与证据关系。
