# 用户需求验证与访谈

根据项目目标设计可执行的定性研究，而不是用虚构访谈证明预设结论。先明确研究目标、人群、场景、关键假设、约束和已有证据；能合理推断的先标注假设，关键缺失信息再询问。

## 工作流程

1. 为每个关键假设写出支持与反驳它的可能观察；明确目标人群、招募条件和访谈用途。不要把便利样本当成总体代表。
2. 用 [访谈与记录模板](assets/interview-guide-template.md) 定制开放式提纲：开场、最近一次真实经历、现有解决方式、阻碍与代价、需求及优先级、结束追问。优先询问过去行为和具体例子，避免诱导问题和仅凭意向判断付费意愿。
3. 开场清楚说明研究目的、使用方式和可退出权利；录音或引用前取得同意。只有确有匿名处理措施时才承诺匿名；按需求最小化记录个人信息。
4. 记录原话、语境、提问、匿名受访者编号和来源；将原话、观察、研究者解释及假设分开。分享前检查同意范围并处理可识别信息。
5. 归纳重复模式与相反案例，记录支持人数、样本限制、未验证问题和下一步。小样本访谈用于发现和探索，不能直接推断总体比例。
6. 输出访谈提纲、记录表、证据台账、初步判断和验证建议；没有实际访谈就标为计划，不编造受访者或原话。

可与 `sasa-business-workflow` 配合：将证据及未验证假设交给商业工作流；图示需求可交给 `sasa-competition-figures`。
