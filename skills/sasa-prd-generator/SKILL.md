# 产品需求文档生成器

依据用户提供的资料生成可供设计、研发和评审使用的 PRD。先记录来源和未知项；不能把假设、示例或 AI 推断当作已经验证的需求。

## 输入与工作流程

1. 整理产品定位、问题、目标用户、使用场景、核心功能、平台形态、商业模式和约束。缺少关键业务决策时集中提出少量问题；其余可暂列假设并继续。
2. 建三张映射表：用户及场景、核心对象和数据字典、激励及商业规则。识别参与角色、权限、状态和异常。
3. 按 [PRD 七模块骨架](references/prd_skeleton.md) 按需组织文档：文档综述；用户及需求；产品结构；全局说明；业务流程；主要功能页面；非功能需求与迭代计划。结合实际任务裁剪，列明优先级和验收标准。
4. 为产品结构、信息架构和关键业务绘制文本或 Mermaid 图。区分角色、触发条件、主路径、分支、失败重试和结束状态；图中节点与正文需求编号对应。
5. 核对用户目标是否映射到功能，功能是否映射到流程、权限、页面状态和验收；记录冲突、开放问题、依赖和待验证假设。
6. 按用户需要输出 Markdown 或 Word。`scripts/generate_prd.py` 接受 JSON 规格而非 Markdown，需 Python 和 python-docx；先检查脚本支持的字段并构造 JSON，运行 `python scripts/generate_prd.py input.json output.docx`，再检查生成文档。不要声称未经渲染检查的文件已经完成排版验收。

## 交付建议

- 关键页面逐项写目标、入口、输入、状态、动作、异常、权限和验收。
- 区分已确认、假设和待决事项；按 P0/P1/P2 说明 MVP 范围。
- 示例只用于说明结构；没有证据的数据必须标为假设。
